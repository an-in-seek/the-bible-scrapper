# BibleGateway 현대인의 성경(KLB) 본문 스크래핑 설계

## 1. 목적

`biblegateway.com`의 현대인의 성경(Korean Living Bible, `version=KLB`) 본문을 수집해 창세기 1장부터 요한계시록 22장까지 66권 전 구절을 적재하는 설계다.

- 예시 URL
  - `https://www.biblegateway.com/passage/?search=Genesis%201&version=KLB`
  - `https://www.biblegateway.com/passage/?search=Psalms%2092&version=KLB`
  - `https://www.biblegateway.com/passage/?search=3%20John%201&version=KLB`
- 판본: 역본 정보 페이지(`/versions/Korean-Living-Bible-KLB/`)의 표기는 `Korean Living Bible (현대인의 성경) Copyright © 1985 by Biblica, Inc.® Used by permission. All rights reserved worldwide.`이다. 같은 페이지의 책 목록은 66권 1,189장이다(KJV 장 수와 같다).
- BibleGateway의 한국어 역본은 둘이다. KLB와 `KOERV`(읽기 쉬운 성경, DB의 translation 4)다. 대상은 KLB뿐이다.

KLB는 [WEB](world-english-bible-scraping-design.md)·[ASV](american-standard-version-scraping-design.md)·[NIV](new-international-version-scraping-design.md)·[ESV](english-standard-version-scraping-design.md)와 **같은 소스, 같은 URL 규칙, 같은 파서**를 쓴다. 이 문서는 앞 문서들을 반복하지 않고 KLB에서 달라지는 점만 다룬다. 그대로 유효한 항목은 아래와 같다.

- URL 생성 규칙과 66권 영문 책명(`BIBLEGATEWAY_BOOK_NAMES`). 역본 정보 페이지의 링크는 한국어 책명(`창세기 1`)을 쓰지만, 영문 책명으로 받은 페이지도 같은 KLB 본문이다(표본 37개 장 모두 `div.version-KLB`)
- 절 번호를 `span.text` 클래스 토큰에서 읽는 규칙, 분할 절 병합
- 각주 제거, `h3` 소제목 제거(본문을 담은 `h3`은 예외, 5.7), `h4` 전체 제거
- `Crawl-delay: 15` 준수(코드에서 하한으로 강제), 전권 적재 때 `--min-delay`
- 장 단위 커밋, missing-only insert, `bible_book` 비생성 계약

## 2. 권리 — 사용자 지시로 진행한다

**KLB는 퍼블릭 도메인이 아니다.** 저작권자는 Biblica이고, NIV와 같은 처지다. 이 문서는 "한국어 '현대인의 성경' KLB 번역본 스크래핑도 필요하다"는 사용자 지시(2026-11-01)에 따라 설계·배선·표본 실측까지 진행한다. 아래 사실은 적재 여부를 판단할 때 다시 봐야 하므로 기록해 둔다.

| 항목 | 확인 내용 |
| --- | --- |
| 저작권자 | Biblica, Inc. BibleGateway 역본 정보 페이지의 출판사와 저작권 표기(2026-11-01) |
| 무허가 인용 한도 | NIV 때 확인한 Biblica 일반 지침: 500절 이하이면서, 성경 한 권 전체가 아니고, 인용하는 저작물의 25%를 넘지 않을 때. 그 이상은 서면 허가가 필요하다. 그때 `biblica.com/permissions`가 403을 돌려줘 2차 출처로 확인했다. **KLB에 따로 적용되는 지침은 확인하지 않았다** |
| 이 설계의 적재량 | 66권, 약 31,104절(4.2). 위 한도의 약 62배이고 모든 책을 통째로 포함한다 |
| BibleGateway 이용약관 | NIV 때(2026-10-05) 확인한 내용이다. "Company Content" 조항이 콘텐츠의 복사·다운로드·보관(archive)·재배포를 금지한다. 이번에 다시 읽지는 않았다 |
| `robots.txt` (2026-11-01 다시 확인) | `/passage/`는 허용, `/bible/*` 일부 차단, `Crawl-delay: 15` |

정리하면 다음과 같다.

- **배선과 표본 실측은 적재 없이 할 수 있다.** 표본은 구조 분석에만 쓰고 DB에 넣지 않았다.
- **KLB 전권 적재는 허가 범위를 넘는다.** NIV·ESV·새번역과 같이 적재(9절)는 별도 게이트로 둔다. 실행 여부는 이 표를 보고 사용자가 결정한다.
- `attribution`을 채울 때 "Used by permission"은 넣지 않는다. 허가를 받지 않았다(NIV와 같은 처리).
- 이 문서는 KLB 본문을 인용하지 않는다. DOM 예시는 구조만 보이고 본문 자리는 `(본문)`으로 표시한다. 편집 표지(`(없음)`, `(여자)` 등)는 본문이 아니므로 그대로 적는다.

## 3. 결론 먼저

**KLB는 지금까지의 파서로 돌리면 조용히 절이 빠진다.** KLB는 몇 절을 묶어 옮긴 곳이 있다(`6-7`). BibleGateway는 그 스팬에 양 끝을 이은 클래스 토큰 하나(`Gen-1-6-Gen-1-7`)를 다는데, 파서의 절 토큰 패턴이 이 형태를 몰라 **스팬째 건너뛰었다.** 표본 37개 장 중 3개 장에서 8절(창 1:6·7·14·15, 2:11·12, 신 6:17·18)이 빠지고, 시 92편은 1절이 `1-3`이라 4절부터 시작해 "첫 절은 1" 가드에 걸려 **장 전체가 건너뛰어졌다.** 앞의 3개 장은 장 끝 절 번호가 그대로라 절 수만 보는 검사로는 찾을 수 없다.

**절 본문 일부가 `h3`에 들어 있는 곳도 있다.** 표본의 `h3` 61개 중 2개(요 8:20, 행 24:2)는 소제목이 아니라 절 중간의 본문 조각이고, 낱말 중간에서 시작한다. `h3`을 모두 지우는 규칙 때문에 그 본문이 사라졌다(5.7). 이 결함은 적재를 시작한 뒤 검토에서 찾았다(12절).

| 항목 | 상태 |
| --- | --- |
| URL 생성, 책명, crawl-delay | 수정 불필요 (`version`을 엔트리 URL에서 승계) |
| **묶음 절 토큰 `Gen-1-6-Gen-1-7`** | **수정함 (2026-11-01)** — 덮는 모든 번호에 같은 본문을 저장한다 (5.1, 6.2) |
| **파싱 실패 페이지의 범용 파서 낙하** | **수정함 (2026-11-01)** — BibleGateway URL은 BibleGateway 파서에서 멈춘다 (6.2) |
| 생략 절 | 표본의 KJV 생략 후보 16곳 중 7곳은 KLB가 자기 스팬에 `(없음)`을 싣고, 9곳은 본문이 있다. 페이지 그대로 저장한다 (5.2) |
| `h3` 소제목, `h4.psalm-title` 시편 표제 | 수정 불필요 — 지금 규칙이 지운다 (5.3) |
| **`h3`에 든 절 본문** | **수정함 (2026-11-01)** — 같은 절 조각이 문장 중간에서 끝난 뒤의 `h3`은 본문으로 되돌린다 (5.7, 6.2) |
| 한국어 띄어쓰기 | 수정 불필요 — 원문 공백을 그대로 쓰고, 분할 스팬 이음 490곳 중 488곳은 시의 줄 경계라 공백 하나로 잇는 것이 맞다. 나머지 2곳은 5.7의 `h3` 자리다 (5.4) |
| 아가 화자 표기 `(여자)`·`(남자)` 등 | **남긴다 (사용자 결정, 2026-11-01)** — 페이지 글자 그대로 저장한다. 위치가 맞다 (5.5, 10절) |
| 엔트리 URL 해석, 정합성 검증 표 | **수정함 (2026-11-01)** — KLB 한 행 추가 (6.1) |
| DB | `bible_translation` 5번 행과 CHECK 값은 **이미 있었다**. `bible_book` 66행과 `attribution`을 넣었다 (2026-11-01, 7절) |
| 적재 | **완료 (2026-11-01–02)** — 66권 / 1,189장 / 31,104절. 사용자가 2절을 보고 지시했고, 이틀에 나눠 받았다 (9절, 12절) |

## 4. 실측 결과

2026-11-01, 이 저장소의 `HolyBibleScraper` 요청 경로로 37개 장을 수집했고, 화자 표기를 보려고 아가 2–8장을 더 받았다(모두 44회). `Crawl-delay: 15` 하한을 지켰고(저장 간격 최소 15.9초), 자동 재시도는 끄고 요청당 한 번만 보냈다. 제한 페이지나 오류는 한 번도 오지 않았다. 페이지는 구조 분석에만 쓰고 DB에 넣지 않았다.

- 수집한 장은 ESV 표본 35개 장(NIV 32개 장 + 눅 22, 계 13, 고후 13)과 같고, 개역개정에서 묶음 절이 확인된 신 6장과 시 92편을 더했다. 아래 표와 대조는 이 37개 장 기준이다.
  - 기본: 창 1, 2 / 신 6 / 욜 2 / 말 4 / 롬 14, 16 / 계 12, 13 / 유다서 / 요삼 / 고후 13
  - 시편과 시: 시 3, 23, 51, 92, 119 / 아 1
  - KJV에 있으나 비평본문이 빼는 절이 있는 장: 마 17, 18, 23 / 막 7, 9, 11, 15 / 눅 17, 23 / 요 5 / 행 8, 15, 24, 28
  - 괄호로 처리되는 본문: 막 16 / 요 7, 8 / 요일 5 / 눅 22

## 5. NIV·ESV와 달라지는 점

### 5.1 묶음 절 — 클래스 토큰 하나에 양 끝이 들어 있다

```html
<p><span class="text Gen-1-5" id="ko-KLB-5"><sup class="versenum">5 </sup>(본문)</span></p>
<p><span class="text Gen-1-6-Gen-1-7" id="ko-KLB-6"><sup class="versenum">6-7 </sup>(본문)</span></p>
<p><span class="text Gen-1-8" id="ko-KLB-7"><sup class="versenum">8 </sup>(본문)</span></p>
```

- 표시 번호는 `6-7`이고, 클래스 토큰은 `책-장-시작절-책-장-끝절`이다. 이 형태는 WEB·ASV·NIV·ESV 페이지에 없었다(6.3).
- 지금까지의 토큰 패턴 `^[A-Za-z0-9]+-(\d{1,3})-(\d{1,3})$`은 이 토큰과 맞지 않아, 파서가 스팬을 절 스팬으로 보지 않고 건너뛰었다. 본문이 통째로 사라지고 경고도 없다.
- 개역개정의 `18-19`(신 6장)와 같은 경우다. 저장소 규칙(bskorea, jpn.bible, wikisource)대로 **묶음이 덮는 모든 번호에 같은 본문을 저장한다.** 절 번호 연속성이 유지되고 어느 번호로 찾아도 본문이 나온다. 대신 같은 본문이 여러 번 들어가므로, 장 단위로 본문을 이어 보여 주는 화면에서는 반복되어 보인다(NKRV·새번역과 같은 처지). 표본에서는 두세 절짜리 묶음뿐이었지만, 첫날 적재분에서 가장 넓은 묶음은 민 7:12–83이다(72절, 12.1).
- 시편처럼 한 묶음이 여러 줄 스팬으로 나뉘어도 토큰이 같으므로 한 절로 이어 붙인다.

### 5.2 생략 절 — `(없음)`을 자기 스팬에 싣는 곳과 본문이 있는 곳

KJV에 있으나 비평본문이 빼는 16곳(NIV의 `(omitted)` 자리)을 KLB는 두 가지로 처리한다.

| 처리 | 좌표 |
| --- | --- |
| 자기 스팬에 `(없음)` (각주 표지가 붙기도 한다) | 막 7:16, 9:44, 9:46, 15:28, 눅 23:17, 행 15:34, 롬 16:24 (7곳) |
| 본문이 있다(괄호로 묶은 곳이 많다) | 마 17:21, 18:11, 23:14, 막 11:26, 눅 17:36, 요 5:4, 행 8:37, 24:7, 28:29 (9곳) |

- `(없음)`은 페이지의 본문 글자이므로 그대로 저장한다. 개역개정 페이지가 생략 절의 자기 스팬에 싣는 값, 새번역 적재 때 쓴 `BSKOREA_OMITTED_VERSE_TEXT`와 같은 글자다.
- 파서는 `(없음)`을 만들지 않는다. 각주만 있고 본문이 빈 스팬에만 `(omitted)`를 쓰는데(WEB 규칙), KLB 표본에는 그런 스팬이 없다.

### 5.3 소제목과 시편 표제

- `h3` 소제목은 지금 규칙으로 지운다. 각 `h3` 안의 스팬이 다음 절의 클래스를 달고 있어, 지우지 않으면 소제목이 그 절 앞에 붙는다. 표본 37개 장의 `h3` 56개 중 54개가 이런 소제목이고, 2개는 본문이다(5.7).
- 시편 표제는 `h4.psalm-title`이다(표본 4개). 다른 역본과 같이 저장하지 않는다. 시 119편에는 히브리 자모 머리글이 없다.
- **시편 권 표제는 `h2`다.** 시 1·42·73·90·107편 첫머리에 `<h2>제 1 권</h2><h4>(1－41)</h4><h3>(소제목)</h3>`이 오고, 셋 다 1절 클래스를 단다. 표본에는 이 다섯 편이 없어 적재 뒤에야 보였다(12.1). 처음 파서는 `h2`를 지우지 않아 권 표제가 1절 앞에 붙었고, 5.7의 규칙은 이 `h2`를 같은 절의 앞 조각으로 보아 뒤의 소제목까지 본문으로 되돌렸다. 이제 `h2`도 지운다(6.2). 같은 `h2`가 WEB(`BOOK 1`)·ASV(`Book I`) 페이지에도 있어, 두 역본은 이 다섯 절 앞에 권 표제를 단 채 적재돼 있었다. 같은 날 제자리 수정했다(6.3, 12.1).
- **다음 시편의 소제목과 표제가 앞 시편 끝에 붙은 페이지가 있다.** 시 130편 페이지는 8절 뒤에 131편의 소제목 `h3`과 표제 `(131편 표제)`를 싣고, 둘 다 `Ps-130-8` 클래스를 단다. 표제는 131편 페이지에서는 `h4.psalm-title`인데, 여기서는 `p.first-line-none` 안의 절 스팬이다. 처음 파서는 소제목을 문장 끝 뒤의 절 중간 `h3`으로 보고 지웠지만, 표제는 8절 끝에 이어 붙였다(공백 포함 21자). 적재 중 경고로 찾았다(12.1). 이제 이 모양이면 표제도 지운다(5.7, 6.2). 넣은 835개 장에서 괄호가 든 시편 절은 이 한 절뿐이었다. NIV·ESV·WEB·ASV의 시 130:8은 깨끗하다.

### 5.4 한국어 띄어쓰기

BibleGateway 파서는 스팬 안의 텍스트를 구분자 없이(`get_text("")`) 읽고, 같은 절의 여러 스팬은 공백 하나로 잇는다. 영어 역본에서 정한 규칙이지만 한국어에도 맞는지 표본으로 확인했다.

- **스팬 이음**: 37개 장에서 한 절 안의 스팬 경계는 490곳이다(`h3`를 지운 뒤 기준). 앞뒤가 모두 한글인 곳이 420곳, 앞이 문장 부호이고 뒤가 한글인 곳이 70곳이다. 488곳은 시의 줄이 바뀌는 자리(`p.line` 안의 `br`)라 원문에는 경계 양쪽에 공백이 없다. 나머지 2곳은 산문의 문단 경계로, 지워진 `h3` 본문의 양쪽이었다(5.7). 처음 쓴 이 문서는 490곳을 모두 정상 이음으로 적었다. 뒤 조각이 조사처럼 보이는 글자(`은`·`의`·`가`·`도`·`들` 등)로 시작하거나 첫 낱말이 한 글자인 39곳을 모두 확인했고, 모두 새 낱말(`의로운`, `들소처럼`, `가까이`, `내`, `더` 등)이었다. 공백 하나로 잇는 규칙이 맞다.
- **각주 표지**: 175개 중 앞이 공백이고 뒤가 한글인 곳이 126개다. 표지가 설명하는 낱말 바로 앞에 붙는다. 지워도 공백이 남는다. 앞뒤가 모두 한글인 5개는 모두 시의 줄 끝에 있어, 다음 줄과는 스팬 이음의 공백으로 띄어진다. 표지를 지워 낱말이 붙는 곳은 없다.
- `CJK_JOIN_PATTERN`(한중일 문자 사이의 이음 공백을 지운다. 한글은 범위 밖)은 BibleGateway 파서에 쓰이지 않는다. eBible·jpn.bible·wikisource 파서의 블록 이음에만 쓰인다.
- **원문 자체의 띄어쓰기 흠**: 몇 절은 페이지의 한 스팬 안에서부터 띄어쓰기가 어긋나 있다. 삼상 25:1 `그 를`, 삼하 19:8 `앉 았다`와 띄어쓰기 없이 이어진 20여 자, 19:18 `도우려 고`. 인쇄본의 줄바꿈 자리로 보인다. 파서가 만든 것이 아니라 페이지 글자 그대로이므로(12.1에서 다시 받아 확인) 고치지 않는다.

### 5.5 아가 화자 표기

KLB 아가는 화자를 괄호 표기로 적는다. 마크업 없는 **일반 텍스트**이고 절 스팬 안에 있다. 아가 8장을 모두 받아 셌다(117절).

| 표기 | 개수 |
| --- | --- |
| `(여자)` | 21 |
| `(남자)` | 11 |
| `(예루살렘 여자들)` | 5 |
| `(여자의 오빠들)` | 1 |

- 위치: 절 첫머리 32개, 한 절 안에서 화자가 바뀌는 절 중간 6개(아 2:10, 5:1, 5:2, 6:13, 7:9, 8:5). 절 끝이나 절 밖에는 없다.
- **새번역과 다른 점**: 새번역은 다음 절부터 말하는 사람을 앞 절 끝에 붙여, 그대로 두면 화자가 틀린 절에 붙는다. KLB는 말이 시작되는 자리에 붙어 있어 위치는 맞다.
- **같은 점**: 원문 번역이 아니라 편집 표기다. 화자 표시가 있는 다른 역본은 모두 지웠다. WEB·NIV는 `h4.speaker`, 새번역은 `(여자)`·`(남자)`·`(친구들)` 텍스트다. 남기면 DB에서 KLB만 아가 본문에 화자 표기를 갖는다.
- 아가의 장별 절 수는 8장 모두 KJV와 같고, 구멍은 없다.

**결정 (2026-11-01)**: 사용자가 "남긴다"를 골랐다. 파서와 `fetch_chapter_payload()`는 바꾸지 않는다. 새번역용 제거(`_strip_bskorea_song_speaker_labels`)는 bskorea URL에만 걸리므로 KLB에는 적용되지 않는다. 그래서 DB에서 아가 본문에 화자 표기가 있는 역본은 KLB 하나다.

### 5.6 그 밖의 확인 사항

- 파싱 결과에 영문 3글자 이상, `[a]`, `N:N` 형태 참조, 이중·가장자리 공백이 있는 절은 0이다.
- 괄호로 시작하는 절은 아가 화자 표기 5절(아 1장), 괄호로 묶은 사본 이문 7절(마 17:21, 18:11, 23:14, 막 11:26, 눅 17:36, 행 8:37, 28:29), 번역자의 괄호 설명 1절(막 7:3)이다. 뒤의 둘은 본문의 일부라 그대로 둔다.

### 5.7 `h3`에 든 절 본문

BibleGateway의 KLB 페이지는 몇 곳에서 절 중간의 본문을 `h3`으로 감싼다. 표본 44개 장의 `h3` 61개 중 2개다.

```html
<p><span id="ko-KLB-25695" class="text John-8-20"><sup class="versenum">20 </sup>(본문)헌금</span></p><h3><span class="text John-8-20">함 (본문)</span></h3><p><span class="text John-8-20">(본문)</span></p>
```

| 위치 | `h3` 길이 | 지웠을 때 |
| --- | --- | --- |
| 요 8:20 | 47자 | `헌금함`이 `헌금`으로 끊기고 47자가 사라진다 |
| 행 24:2 | 1자(`한`) | `탁월한 지도력`이 `탁월 지도력`이 된다 |

- 소제목과 구조가 다르다. 소제목 59개는 모두 그 절의 **첫 스팬**이라 `id`를 달고, 앞에 공백이 있다(`</p> <h3>`). 본문 `h3` 2개는 같은 절의 앞 조각 **뒤**에 오고, `id`가 없으며, 앞뒤에 공백 없이 붙어 있다(`</p><h3>`, `</h3><p>`). 두 곳 모두 낱말 중간에서 시작한다.
- 절 중간 `h3`이 모두 본문은 아니다. ESV 표본의 절 중간 `h3` 2개(막 16:9, 요 7:53)는 괄호 안내문 `[…]` 뒤에 오는 진짜 소제목이다. KLB에도 있다. 창세기 1–35장을 다시 받아 보니 창 29:14와 35:22에서 문장 끝(`…다.`) 뒤에 짧은 소제목이 절 중간에 있었다(12절). 이 둘은 `id`가 없고 앞에 공백도 없어서, 위의 `id`·공백 차이로는 본문과 가를 수 없다.
- 그래서 규칙은 이렇다. **`h3` 안 스팬의 절이 바로 앞 절 스팬과 같고, 그 앞 조각이 글자(한글·영문·숫자)로 끝나면 본문이다.** 소제목은 문장 중간에 끼어들지 않는다. 본문 `h3`은 앞 조각 끝에 공백 없이 붙이고, 다음 조각은 지금처럼 공백 하나로 잇는다. 두 곳 모두 이렇게 해야 원문이 된다(`헌금함 앞에서 … 사람이 아무도`, `탁월한 지도력`). 원문에 공백이 없는 자리라 이음 규칙은 이 두 곳에서 정한 것이다.
- 절 중간 `h3`은 본문으로 되돌리든 소제목으로 지우든 모두 경고 로그를 남긴다. 적재 뒤 로그의 좌표를 하나씩 확인한다(8절).
- "바로 앞 절 스팬"은 **다른 제거 대상을 모두 지운 뒤**의 스팬이다. 처음 구현은 `h3`·`h4` 안의 스팬만 건너뛰고 컨테이너 정리 전에 판정해서, 시 1:1과 42:1에서 `h2` 권 표제(`…권`, 글자로 끝남)를 앞 조각으로 보고 소제목을 본문으로 되돌렸다(5.3, 12.1). 이제 `h3` 외의 제거 대상을 먼저 지우고, 판정한 뒤, 남은 `h3`을 지운다.
- 문장 끝 뒤의 절 중간 `h3`을 소제목으로 지울 때 확인할 것이 하나 더 있다. 그 뒤로 페이지 끝까지 같은 절의 스팬만 남고, 그 글자가 괄호 한 덩어리뿐이면 다음 장의 표제가 넘어온 것으로 보고 함께 지운다(5.3의 시 130편). 괄호 뒤에 본문이 더 있거나 다른 절이 이어지면 지금처럼 본문으로 둔다. 근거가 한 곳뿐이라 이 판정은 따로 경고를 남기고, 구동 스크립트도 그 장 뒤에서 멈춘다(9절).
- **본문 `h3`이 낱말 경계에서 시작하는 곳도 있다.** 마 9:17은 `…쓰게</span></p><h3><span class="text Matt-9-17">된다.</span></h3>`로, 앞 조각과 공백 없이 이으면 `쓰게된다`가 된다. KLB는 다른 83절에서 `-게 된`을 띄어 쓰고, 붙여 쓴 곳은 이 절뿐이었다. 마크업은 요 8:20·행 24:2(낱말 중간)와 똑같아(`</p><h3>`, 공백 없음) 구조로는 가를 수 없다. 그래서 페이지를 보고 확인한 절만 `BIBLEGATEWAY_SPACED_HEADING_TEXT_TOKENS`에 적어 공백 하나로 잇는다(지금은 `Matt-9-17` 하나). 목록에 없는 절은 지금처럼 붙여 잇고, 구동 스크립트는 검토하지 않은 되돌림마다 멈춘다(9절).
- 절 첫머리의 본문 `h3`(절의 첫 낱말을 `h3`에 넣은 경우)은 구조로 소제목과 가를 수 없다. 표본에는 없다. 소제목 59개는 길이 2~25자이고 문장 끝 부호로 끝나는 것은 물음표 하나다.

## 6. 코드 변경 지점

### 6.1 `scrape_bible_to_db.py`

- `ENTRY_URL_ENV_BY_TRANSLATION_TYPE`에 `KLB: KLB_ENTRY_URL`
- `TRANSLATION_TYPES_BY_LANGUAGE_CODE["ko"] = ("NKRV", "RNKSV", "KRV", "KLB")`
- `ENTRY_URL_PREFERENCE_ORDER` 끝에 `KLB`
- `TRANSLATION_SOURCE_REQUIREMENTS["KLB"] = {"source": "biblegateway", "version": "KLB", "name": "현대인의 성경", "language_code": "ko"}`

`version`이 정확히 맞아야 하므로 같은 사이트의 `KOERV` URL은 KLB 행에 들어가지 않고, 소스가 달라 bskorea URL도 들어가지 않는다. 책명은 `resolve_book_code_for_source()`가 DB의 책 이름이 아니라 `BIBLEGATEWAY_BOOK_NAMES`에서 고르므로, `bible_book`에 한국어 책 이름을 넣어도 URL은 영문 책명으로 만들어진다.

### 6.2 `scraper.py`

1. **`BIBLEGATEWAY_VERSE_CLASS_PATTERN`**이 묶음 토큰을 받는다: `^([A-Za-z0-9]+)-(\d{1,3})-(\d{1,3})(?:-([A-Za-z0-9]+)-(\d{1,3})-(\d{1,3}))?$`
2. **`_extract_verses_from_biblegateway_passage()`**는 조각마다 `(장, 시작절, 끝절)`을 들고, 병합 단계에서 시작절부터 끝절까지 모든 번호에 조각을 붙인다. 아래는 추측하지 않고 경고와 함께 `[]`를 돌려준다(장은 건너뛰어진다).
   - 다른 책이나 다른 장으로 넘어가는 묶음(`Gen-1-31-Gen-2-1`). 장을 넘는 묶음은 어느 장에 저장할지 정할 수 없다
   - 거꾸로 된 묶음(`Gen-1-8-Gen-1-7`), 폭 1인 묶음
   - 한 번호가 두 단위에 들어 있는 경우(`Gen-1-6-Gen-1-7`과 `Gen-1-7`이 함께 있음)
3. **`_restore_biblegateway_verse_text_in_headings()`** (새 메서드): `h3` 외의 제거 대상을 지운 뒤 절 중간 `h3`을 찾아 5.7의 규칙대로 본문을 앞 조각에 되돌린다. 판정마다 경고 로그를 남긴다. 남은 `h3`은 그다음에 지운다.
4. **`_extract_verses()`**: BibleGateway URL이면 BibleGateway 파서가 `[]`를 돌려줘도 체인을 멈춘다. bskorea와 같은 처리다. 이전에는 범용 파서로 넘어갔고, 범용 파서는 BibleGateway 페이지의 각주와 메뉴를 절로 읽는다(파서 체인 주석). 2번의 거부가 실제로 장을 건너뛰게 하려면 이 처리가 필요하다.
5. **`BIBLEGATEWAY_CONTAINER_REMOVABLE_SELECTOR`**에 `h2`(시편 권 표제, 5.3)를 넣었다. 저장해 둔 BibleGateway 페이지 130개(ESV 36, KLB 84, WEB·ASV 시편 10)에서 `passage-content` 안의 `h1`·`h2`·`h5`·`h6`은 `h2` 12개뿐이고, 모두 권 표제다. KLB 시 1·42편과 WEB·ASV 시 1·42·73·90·107편이다. 근거가 이 다섯 자리뿐이므로, 다른 절 클래스를 단 `h2`는 지우되 경고를 남긴다(`BIBLEGATEWAY_PSALTER_BOOK_HEADING_TOKENS`).
6. **`_biblegateway_spilled_chapter_title()`** (새 메서드): 3번이 문장 끝 뒤의 `h3`을 소제목으로 지울 때 부른다. 그 `h3` 뒤의 절 스팬이 모두 같은 절이고, 각주 번호를 뺀 글자가 괄호 하나(`\([^()]*\)`)이면 그 스팬들을 돌려준다. 3번은 그 스팬도 지우고 다른 경고(`dropped with it as the next chapter's heading`)를 남긴다(5.7).
7. **`BIBLEGATEWAY_SPACED_HEADING_TEXT_TOKENS`** (새 상수): 3번이 본문으로 되돌린 `h3`을 앞 조각에 붙일 때, 이 목록의 절이면 공백 하나를 먼저 넣는다. 페이지에서 낱말 경계로 확인한 절만 적는다(5.7).

### 6.3 기존 영어 역본에 미치는 영향

- 저장해 둔 ESV 표본 36개 장을 수정 전(HEAD) 파서와 수정 뒤 파서로 읽어 비교했다. **36개 장 모두 같다.** `h3` 수정 뒤에도 같다. 절 중간 `h3` 2개는 소제목으로 판정돼 계속 지워진다(5.7). KLB 표본 37개 장은 묶음 절이 있는 4개 장만 다르고, 그 4개 장도 묶음 번호가 새로 생긴 것뿐이다(원래 읽히던 절의 본문 변화 0).
- DB의 WEB·ASV·NIV·ESV에는 묶음 토큰 때문에 빠진 절이 없다(2026-11-01 읽기 전용 조회). KJV에만 있는 좌표는 WEB 3(롬 16:25–27, 14:24–26으로 옮긴 송영), ASV 16, NIV 0, ESV 17이고, ASV·ESV의 것은 정해 둔 생략 절 목록과 정확히 같다. 장 안의 구멍도 그 생략 절뿐이다(WEB 0, NIV 0, ASV 16, ESV 17). 묶음이 장 중간에 있었다면 구멍이, 장 끝에 있었다면 KJV에만 있는 좌표가, 장 첫머리에 있었다면 장 전체가 빠졌을 것이다.
- 체인 멈춤은 BibleGateway 파서가 아무것도 못 읽은 페이지에서만 동작이 달라진다. 그런 장은 이제 범용 파서의 추측 대신 "No verses parsed" 경고와 함께 건너뛰어진다.
- `h2` 제거와 판정 순서 변경(6.2의 3·5번)은 저장한 BibleGateway 페이지 120개(ESV 36, KLB 표본 44, KLB 재확인 40)를 직전 커밋(84c7975)의 파서와 견줘 확인했다. 달라진 곳은 KLB 시 1:1과 42:1 두 절뿐이고, 둘 다 권 표제·소제목과 이음 공백만큼(13자, 18자) 짧아졌다.
- 다음 장 표제 제거(6.2의 6번)는 저장한 BibleGateway 페이지 131개(ESV 36, KLB 표본 44, KLB 재확인 41, WEB·ASV 시편 10)를 직전 커밋(1a64d07)의 파서와 견줘 확인했다. 달라진 곳은 KLB 시 130:8 한 절이고, 공백과 표제만큼(21자) 짧아졌다.
- 띄어 잇는 목록(6.2의 7번)은 저장한 페이지 133개(위 131개와 KLB 마 9장·미 5장 재확인 2개)를 직전 커밋(accf130)의 파서와 견줘 확인했다. 달라진 곳은 KLB 마 9:17 한 절이고, 공백 하나만큼 길어졌다. 요 8:20과 행 24:2는 그대로다.
- **DB의 WEB·ASV에는 시편 권 표제가 남아 있었다**(2026-11-01 읽기 전용 조회). 시 1·42·73·90·107편 1절이 WEB은 `BOOK 1 `~`BOOK 5 `로, ASV는 `Book I `~`Book V `로 시작했다(10행). 같은 날 사용자 지시로 제자리 수정했다(12.1). NIV·ESV에는 없다. 페이지에 권 표제가 `h2`로 있었다면 같은 모양으로 들어갔을 것이므로, 두 역본의 페이지에는 그런 `h2`가 없었던 것으로 본다(이 다섯 장은 표본에 없어 확인하지 않았다).

## 7. DB 준비

현재 상태(2026-11-01 실측, 읽기 전용 조회):

| 항목 | 상태 |
| --- | --- |
| `bible_translation` | **id 5, `KLB`, `현대인의 성경`, `ko`, `translation_order` 5 행이 이미 있다.** `attribution`은 NULL |
| `translation_type` CHECK | `KLB` **이미 포함** |
| `bible_book` / `bible_chapter` | 0 / 0 |
| `bible_book` 최대 id | 1110. identity는 `BY DEFAULT` |

DDL은 필요 없다. `bible_book` 66행은 새번역 때와 같이 개역개정(2) 행을 복사한다(한국어 책 이름).

```sql
SELECT setval('public.bible_book_id_seq', (SELECT COALESCE(MAX(id), 0) FROM public.bible_book), true);

INSERT INTO public.bible_book
    (translation_id, book_order, book_key, name, abbreviation, testament_type)
SELECT 5, src.book_order, src.book_key, src.name, src.abbreviation, src.testament_type
FROM public.bible_book src
WHERE src.translation_id = 2
  AND NOT EXISTS (
      SELECT 1 FROM public.bible_book dst
      WHERE dst.translation_id = 5 AND dst.book_order = src.book_order
  )
ORDER BY src.book_order;

UPDATE public.bible_translation
SET attribution = 'Korean Living Bible (현대인의 성경) Copyright © 1985 by Biblica, Inc.® All rights reserved worldwide.'
WHERE id = 5 AND attribution IS NULL;
```

- 이 SQL은 도구 밖에서, 사용자가 요청할 때만 실행한다. 도구는 `bible_book`을 만들지 않는다.
- **실행 (2026-11-01)**: 사용자가 적재를 지시한 뒤 위 SQL과 같은 일회성 스크립트로 넣었다. 66행(id 1111–1176, 구약 39 / 신약 27)이 개역개정 행과 전 열 일치하는 것을 확인한 뒤 커밋했고, `attribution`도 위 값으로 채웠다.
- `attribution`은 역본 정보 페이지의 표기에서 "Used by permission."만 뺀 것이다(2절).

## 11. 리스크

### 리스크 1. KLB 본문이 다른 한국어 역본 행으로 들어간다

정합성 검증 표가 막는다. KLB URL은 `version=KLB`일 때만 translation 5와 맞고, 개역개정·개역한글·새번역 행에는 소스부터 맞지 않는다.

### 리스크 2. 표본 밖의 묶음이 장을 넘거나 겹친다

파서가 그 장을 거부하고(경고), 구동 스크립트가 멈춘다. 그때 페이지를 보고 저장 방법을 정한다. 거부하지 않고 추측하면 틀린 장에 본문이 들어가고, 어떤 검사도 그것을 찾지 못한다.

### 리스크 3. 권리 상태를 잊는다

NIV·ESV·새번역에 이어 이 DB에 저작권 역본이 하나 더 들어간다. README와 CLAUDE.md의 소스 표에 저작권 역본으로 적어 둔다.

### 리스크 4. 요청 제한

9절대로 이틀에 나눈다. 제한 페이지가 보이면 그날은 멈춘다.
