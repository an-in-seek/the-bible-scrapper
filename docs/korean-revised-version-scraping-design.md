# 대한성서공회(`bskorea.or.kr`) 개역한글(KRV) 본문 스크래핑 설계

## 1. 목적

DB의 `KRV` 행(`bible_translation.id = 1`, 이름 `개역한글`)을 대한성서공회가 게시한 **성경전서 개역한글판**(1961, `version=HAN`) 본문과 같게 만드는 설계다.

- 예시 URL: `https://www.bskorea.or.kr/bible/korbibReadpage.php?version=HAN&book=gen&chap=1&sec=1&cVersion=&fontSize=15px&fontWeight=normal`
- 이 행은 이 도구로 적재한 적이 없다. 이미 31,102절이 들어 있었지만 출처가 다른 디지털 본문이었고, 2026-10-31 전권 대조(4절)에서 개역한글 페이지와 본문이 다른 절이 873개 나왔다. 2026-11-01에 본문을 개역한글 페이지로 바꿨다(6–7절).
- 개역한글은 [개역개정(NKRV)](nkrv-scraping-design.md)·[새번역(RNKSV)](revised-new-korean-standard-version-scraping-design.md)과 **같은 소스, 같은 URL 규칙, 같은 파서**를 쓴다. 파서 변경은 없다. 새번역 작업에서 고친 bskorea 경로(요나 `jnh`, 깊이와 상관없는 절 탐색, 병합 절 번호, 절 중간 소제목)가 그대로 적용된다.

## 2. 권리

대한성서공회 저작권안내 페이지(`co_id=subpage2_3_4_1`)의 보호기간 표에서 개역한글판(1961)은 **2011-12-31에 저작재산권 보호기간이 소멸했다**(2026-10-29 확인, [새번역 설계 문서](revised-new-korean-standard-version-scraping-design.md) 2절). 개역개정·새번역과 달리 이 행은 배포 제한이 없다. `attribution`은 이미 `성경전서 개역한글판 — 대한성서공회`이고 바꾸지 않는다. `robots.txt`는 없다(404).

이 문서는 퍼블릭 도메인인 개역한글 본문을 짧게 인용한다. 개역개정 본문은 대조의 증인으로만 썼고 옮기지 않는다.

## 3. 결론 먼저

- **배선**: `TRANSLATION_SOURCE_REQUIREMENTS`에 `KRV`(`bskorea`, `version=HAN`, `개역한글`, `ko`) 행을 넣었다. `ko`는 이제 NKRV·RNKSV·KRV 셋을 가리키고, `KRV_ENTRY_URL`을 받는다. bskorea의 세 번역은 `version`으로만 구별되므로 `GAE`·`SAENEW`·version 없는 URL은 KRV 행에 넣지 않는다.
- **파서는 그대로다.** 저장한 1,189장을 현재 파서로 모두 읽었고 거부된 장이 없다.
- **1961년 표기는 원문이다.** 페이지는 `할쌔`, `사냥군`, `세째`, `십륙`, `가까왔다`, `일찌기`로 쓴다. 파서가 현행 맞춤법으로 바꾸면 원문이 아니게 되므로 바꾸지 않는다.
- **기존 DB 본문은 원문과 달랐다.** 대조 결과(4절)를 보고 사용자가 원문으로 바꾸기로 정했다. 지우지 않고 장마다 `text`만 바꿨고(6절), 이제 DB는 저장한 페이지와 글자 단위로 같다(7절).

## 4. 전권 대조 (2026-10-31, 읽기 전용)

### 4.1 방법

- 개역한글 1,189장을 3~6초 간격으로 받았다(약 1시간 30분, 연결 끊김 재시도 2번, 429·속도 제한 0번). 받은 페이지를 `fetch_chapter_payload`로 읽어 DB `translation_id = 1`과 절마다 견줬다.
- 띄어쓰기와 `찌/지`·`찐/진`은 무시했다. 1961년 맞춤법 대응 17종(4.4절)과 문장부호만 다른 절은 따로 셌다.
- 짧은 차이에는 같은 DB의 개역개정(id 2)을 세 번째 증인으로 썼다. 그 자리의 개역개정이 개역한글과 같으면 DB만 다른 것이다.

### 4.5 오기처럼 보이는 1961년 낱말

짧은 차이 중에는 개역한글이 틀린 것처럼 보여도 원문이 맞는 곳이 많다. 대조 중 "페이지 쪽 오기"로 골랐던 다섯 곳 중 네 곳이 그랬다.

- 막 13:19 `창조하신 창초부터`: 창초(創初)다. DB는 `창조부터`
- 사 19:6 `달과 갈이 시들겠으며`: 달·갈은 갈대 종류다. DB는 `달과 같이`
- 대상 4:4 `그돌의 아비`: 지명이다. DB는 `그들의`
- 대상 9:9 `구백오십륙 인이니 다 그 집의 족장된 자들이더라`: `다`는 "모두"다. DB는 `인이니라 그 집의`

반대로 개역한글 페이지가 틀렸을 수 있는 곳(예: 행 2:9 `엘림인`, 개역개정과 DB는 `엘람인`)은 다른 개역한글 인쇄본과 견줘야 판정할 수 있다. 본문을 바꾼 뒤 DB는 이런 곳도 페이지 그대로다.

## 5. 코드 변경

`scrape_bible_to_db.py`만 바뀐다.

- `ENTRY_URL_ENV_BY_TRANSLATION_TYPE`에 `KRV: KRV_ENTRY_URL`
- `TRANSLATION_TYPES_BY_LANGUAGE_CODE["ko"] = ("NKRV", "RNKSV", "KRV")`
- `ENTRY_URL_PREFERENCE_ORDER` 끝에 `KRV`
- `TRANSLATION_SOURCE_REQUIREMENTS["KRV"] = {"source": "bskorea", "version": "HAN", "name": "개역한글", "language_code": "ko"}`

`get_source_version()`은 bskorea URL에 `version=`이 없으면 `GAE`를 보고하므로 version 없는 URL은 KRV 행과 맞지 않아 중단된다. 책 코드(요나 `jnh`)와 장 수(`KJV_CHAPTER_COUNTS`)는 그대로 쓴다.

테스트(`tests/test_pipeline.py`, 4개 추가):

- HAN URL은 KRV 메타데이터와 맞는다. `translation_type`이 비어 있으면 이름·언어로 맞는다
- HAN URL + NKRV/RNKSV 메타데이터, GAE/SAENEW/version 없는 URL + KRV 메타데이터는 모두 `Source/translation mismatch`로 중단된다
- `BIBLE_TRANSLATION_TYPE=KRV`이면 `KRV_ENTRY_URL`을 고른다
- `BIBLE_LANGUAGE_CODE=ko`만 주고 한국어 URL이 둘 이상이면 중단한다

## 6. 운영 — 지우지 않고 장마다 본문만 바꿨다

사용자는 처음에 "원문으로 다시 적재"를 골랐다. 지우기 전에 아래 사실을 알리자, 사용자가 **장마다 본문만 교체**하기로 정했다(2026-11-01).

- **앱이 이 DB를 쓰고 있다.** 다른 표가 절을 가리킬 때는 행 ID가 아니라 `(translation_id, book_order, chapter_number, verse_number)`를 쓴다(`bible_verse_highlight`의 KRV 하이라이트 224개 등). `bible_verse`·`bible_chapter`를 가리키는 외래 키는 없다.
- **지우고 다시 적재하면 그동안 KRV가 빈다.** 적재기는 장 단위로 넣으므로 약 1시간 30분 동안 아직 안 들어간 책이 앱에서 비어 보인다.
- **좌표가 양쪽에서 같다**(4.2절). 넣거나 지울 절이 없고, 다른 것은 8,718절의 `text`뿐이다.

그래서 적재기 대신 일회성 스크립트로 `text`만 `UPDATE`했다. 저장소의 "지우고 다시 적재" 규칙(CLAUDE.md)과 다르지만, 적재기의 missing-only 계약은 건드리지 않았다. 스크립트는 커밋하지 않았고 동작은 아래와 같다.

- 입력: 2026-10-31에 저장한 1,189장. 적재 직전에 10장(창 1, 출 25, 민 1, 시 46, 시 119, 렘 32, 렘 52, 욘 1, 막 13, 계 19)을 적재기 경로(`fetch_chapter_payload`)로 다시 받아 저장본과 견줬고, 10장 모두 같았다.
- 장마다 한 트랜잭션이다. 앱에는 바뀌기 전이나 바뀐 뒤의 장만 보이고, 빈 장은 보이지 않는다.
- 파싱 결과가 비었거나, 1절로 시작하지 않거나, 절 번호 집합이 DB와 다르거나, 빈 절이 있는 장은 쓰지 않는다. 해당한 장은 없었다.
- `UPDATE … WHERE id = %s AND chapter_id = %s AND text = %s`로 옛 본문까지 맞을 때만 바꾼다. 한 행이라도 `rowcount`가 1이 아니면 그 장을 되돌리고 멈춘다.
- 세션 설정은 바꾸지 않는다(CLAUDE.md의 트랜잭션 범위 규칙).
- 먼저 `--dry-run`으로 8,718절, 건너뛴 장 0, 바뀌지 않는 장 18을 확인한 뒤 적용했다.

바꾸기 전 31,102행(`id`, `chapter_id`, 좌표, `text`)은 `.omc/backups/krv_translation1_before_han_2026-11-01.jsonl`(git 제외, sha256 `7beffa30…63bd84`)에 있다. 되돌릴 때는 이 파일의 `text`로 같은 `id`를 `UPDATE`하면 된다.

**`bible_word_stat`은 낡았다.** KRV 장별 단어 통계(108,221행, 2026-08-27 계산)는 옛 본문에서 계산한 값이다. 다시 계산하는 것은 이 저장소 밖의 일이다.

## 8. 남은 일

- `bible_word_stat`의 KRV 통계를 다시 계산한다(이 저장소 밖).
- 행 2:9 `엘림인`처럼 개역한글 페이지 쪽 오기로 의심되는 곳은 다른 개역한글 인쇄본과 견줘야 판정할 수 있다. 지금 DB는 페이지 그대로다.
